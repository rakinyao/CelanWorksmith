# Map Chart 中国省级边界数据设计

## 背景

当前 Map Chart 随前端仓库内置了多份来源不明的地图边界文件（世界、洲、北美、美国等），并通过 ECharts 注册后按地图类型加载。本次改造只关注中国区域展示，不能继续依赖这些未留档来源的默认资源。

## 范围

- 删除当前 `app/client/public/static/maps/` 下现有的旧边界资源，不与新资源并存。
- 引入经过确认来源的中国省级全国 GeoJSON，作为 Map Chart 的全国视图。
- 全国视图包含所有省级要素；即使某省没有省内下级数据，也必须显示其边界、名称和全国级数值。
- 省内下钻资源按省提供本地静态 GeoJSON，运行时按需加载；只为实际存在并通过核验的省份提供省内选项。
- 本阶段不实现 Builder、色阶编辑、地市级数据编辑器或普通 Map Widget 改造。
- 浏览器运行不依赖互联网；加载失败时不得回退到远程 API。

## 数据契约

全国地图资源采用阿里云 DataV 行政区划 GeoJSON 的已确认版本，固定保存为项目静态资源。省级要素使用 `properties.adcode` 的字符串值作为区域 ID，`properties.name` 作为中文显示名称。全国数据仍使用现有 `{ id, value }` 数组，不改变 Action、DSL 或 `selectedDataPoint` 的公开字段。

全国资源中没有下级数据的省份仍属于有效全国区域。省内资源清单单独维护，省份只有在对应本地文件存在且通过结构核验时才出现在省内操作入口；缺失省内资源的省份不提供下钻操作，但不从全国地图中移除。

## 资源与加载

- 全国资源使用一个稳定的本地文件和版本标识。
- 省内资源按行政区划代码命名，例如 `330000_full.json`，由本地静态服务提供。
- 加载器继续使用 ECharts `registerMap`，但将远程 URL 替换为受清单约束的本地路径。
- 每个资源在提交前校验 `FeatureCollection`、要素 `adcode`/`name`、层级字段和几何类型；特殊边界要素可以保留在 GeoJSON 中，但不得作为可填色的业务区域。
- 删除旧资源后，旧地图类型不再出现在新建选项中。已有旧配置不得静默请求公网；应显示可理解的资源不可用状态，具体兼容提示在实施计划中落实。

## 交互与错误处理

全国地图展示所有省级区域及其名称；省内下钻仅对资源清单中的省份可用。没有省内资源时保持全国视图。资源加载失败显示 Map Chart 现有错误边界或等价的可恢复错误，不阻塞编辑器。

区域点击仍返回现有 `selectedDataPoint` 结构，使用稳定的 `originalId`、规范化 `id`、名称和数值。未知或特殊要素不可点击为业务数据，不能导致运行时异常。

## 验证

- 静态资源清单覆盖全国省级要素；各省资源的层级和要素数量与来源记录一致。
- 无网络环境下，全国地图和已提供省内地图仍可加载。
- 缺失省内资源的省份在全国视图正常显示，省内操作不出现。
- 旧地图资源文件和旧资源路径不再被代码引用。
- 覆盖加载、区域 ID 映射、特殊要素过滤、点击数据和资源失败状态的自动化测试。

## 未纳入本阶段

世界国家级新边界资源、全国地市级完整覆盖、地图 Builder、色阶 Builder、主题扩展和普通 Map Widget 均不在本次实现范围内。
