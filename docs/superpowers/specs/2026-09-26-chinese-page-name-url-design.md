# 中文页面名称与 URL 兼容修复设计

日期：2026-09-26

状态：方案已在会话确认；本文为实施前设计审核稿。

## 目标与边界

允许应用中的所有 Pages 使用中文显示名，并保持编辑、发布、直达、刷新和导航时的页面身份稳定。沿用原生 Appsmith 页面模型、发布流程和路由，不引入拼音库或平行路由系统。

页面名称、普通 URL 的可读 slug、静态 URL 的唯一 slug 分别承担展示、可读性和地址定位职责。不得将空 slug 相等解释为中文名称重复。

不批量重写历史普通 slug，不修改页面 ID，不自动启用静态 URL 功能，不修改现有功能开关和权限边界。

## 已确认根因

1. `PageSettings.tsx` 将页面名过滤为 URL 字符串，再比较其他页面的 slug。纯中文名称被过滤为空，造成误报。上一轮已增加空值防护和定向测试，当前仍为未提交修改。
2. `URLAssembly.ts` 的普通 URL 生成已有 `page` 回退，但 `getPagePathPreview` 会以未经回退的页面名覆盖它，形成 `/-<页面ID>`。
3. `helpers.tsx` 的 `splitPathPreview` 使用 `url.split(pageSlug)`。当 pageSlug 为 `-` 时，应用名称中的连字符也被拆分；界面只渲染前四段，导致预览截断。正常 slug 与应用名称重复时也有同类风险。
4. `StaticUrlServiceImpl.java` 在启用静态 URL 时跳过空普通 slug 的页面；导入和复制入口也有跳过空唯一 slug 的逻辑。仅修复名称输入不足以覆盖静态发布。

## 字段契约

| 字段 | 规则 |
| --- | --- |
| pageName / name | 保留中文显示名，沿用文件名限制与长度限制。同应用内真正同名仍拒绝。 |
| slug | 保留现有生成规则；普通 URL 组装时空值回退为 `page`，不必回写历史数据。 |
| basePageId | 普通 URL 的页面定位依据；名称或 slug 变化不得改变此 ID。 |
| uniqueSlug | 静态模式下必须非空且唯一；持久化后不因页面重命名而自动变化。 |
| customSlug | 保留现有带 ID 的自定义 URL 行为；不能与无 ID 的静态 URL 混为一谈。 |

## 普通 URL 与名称校验

- 预览与运行时复用相同的空 slug 回退逻辑，纯中文页面使用 `/app/<应用slug>/page-<页面ID>`。
- URL 高亮按实际路由片段位置拆分，不能用全局字符串拆分。各段重新拼接必须等于完整 URL。
- 保持旧的带 ID 地址可解析，包括英文 slug 地址和已有空可读前缀地址。
- 名称重复与 slug 冲突分别校验。前端改善即时反馈，服务端保留最终名称唯一性校验；先确认现有入口，避免重复实现或改变大小写语义。
- 对未改变的名称和当前页面自身不报冲突。非空 slug 的现有冲突规则保持兼容。

## 静态 URL 分配

仅在现有静态 URL 能力及应用配置允许时运行，不通过本修复开启该能力。

候选标识按以下优先级确定：保留有效且无冲突的已有 uniqueSlug；否则使用有效普通 slug；否则使用 `page`。自动生成候选发生冲突时依次尝试 `page-1`、`page-2` 等编号，直到找到可用值。

分配前先保留所有有效的已有标识，避免新页面抢占后续页面已有的地址；同批新分配的标识也立即加入占用集合。分配结果必须持久化，不能在浏览器或每次读取时临时编号。重复执行应保持结果稳定。

手动输入的重复标识应返回冲突，不能悄悄替换为带后缀版本。最终唯一性由服务端负责；实现时需检查并发写入保护，不能把单次内存集合检查等同于数据库并发保证。

## 生命周期与兼容性

- 启用静态 URL：为包括纯中文在内的全部有效页面分配标识，不再跳过空普通 slug。
- 新建页面：在静态模式下分配非空且唯一的标识。
- 重命名：修改显示名及原生普通 slug，不重新分配已有有效 uniqueSlug。
- 复制页面：新页面拥有独立标识，不能复用源页面地址。
- 导入页面：覆盖同一页面时保留身份语义；新增页面才分配新的无冲突标识。保持现有 Git sync ID、分支和应用隔离。
- 存量缺失标识：在明确的写入/修复流程中幂等补齐未发布数据；通过原生发布流程生效，不在读取接口偷偷写库或越过发布过程修改已发布版本。
- 存量重复有效标识：先报告涉及页面及冲突地址，不自动选择旧地址的新归属。该地址原本就不能唯一标识多个页面，修复需要明确归属并重新发布。
- 已有正常地址不得批量改写。应用级 slug 生成不属于本轮扩展范围。

## 实施顺序与代码范围

### 第一阶段：普通模式闭环

涉及 `app/client/src/pages/AppIDE/components/AppSettings/components/PageSettings.tsx`、`AppSettings/utils.ts`、`app/client/src/ce/entities/URLRedirect/URLAssembly.ts` 和 `app/client/src/utils/helpers.tsx` 及对应定向测试。

先以双中文页面、带连字符应用名和重复文本路径复现，再修复预览回退、精确拆分及名称校验。检查服务端页面重命名入口，确认真实重名依旧拒绝。

### 第二阶段：静态模式闭环

涉及 `app/server/appsmith-server/src/main/java/com/appsmith/server/staticurl/StaticUrlServiceImpl.java` 及实际调用的创建、复制、导入和发布入口。编写服务端定向测试覆盖分配、保留、冲突及幂等性，再接入原生流程。

先检查静态功能开关及当前环境是否可验证，不绕过功能开关。先完成只读存量诊断，不直接修改用户应用数据；涉及重复已发布地址时请求用户确认修复归属。

### 第三阶段：发布验收

使用专门的测试应用验证两个中文页面，避免修改用户业务应用。分别覆盖普通模式与可用时的静态模式。记录浏览器验证、服务端测试和环境限制，未验证项不得写成通过。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 两个不同纯中文名称 | 保存成功，不因空 slug 误报冲突 |
| 真正同名 | 与既有名称规则一致地拒绝，包含直接 API 调用 |
| 中文、混合英文、英文名称 | 普通发布 URL 含正确页面 ID |
| 应用名称包含多个连字符 | 预览完整，不丢失应用或页面片段 |
| 应用 slug 和页面 slug 有相同文本 | 只高亮页面片段，拼接后 URL 不变 |
| 普通模式两中文页面 | 发布、直达、刷新和导航分别到达对应页面 |
| 普通页面重命名 | ID 不变，旧的带 ID 链接仍定位原页面 |
| 静态模式两中文页面 | uniqueSlug 非空、不重复、持久化后稳定 |
| 静态名称重命名 | 已发布地址不自动变化 |
| 已有 `page`、`page-1` | 自动分配避开已占用标识 |
| 创建、复制、导入 | 无缺失/重复标识，保持应用及 Git 身份隔离 |
| 存量缺失及重复地址 | 缺失可幂等补齐；重复先诊断，不静默改变地址归属 |
