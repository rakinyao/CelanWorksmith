# 发布预检原生资源兼容设计

日期：2026-09-27

状态：设计已确认，Task 1-3 已实施并通过逐任务审查；68 项服务端和 25 项客户端定向测试通过。整体最终审查通过，无遗留阻断问题；授权环境发布验收与真实视口检查未完成。详细命令、计数和限制见[实施计划的实际状态](../plans/2026-09-27-release-preflight-native-resource-compatibility-plan.md#状态)。

## 目标

修复发布预检将合法 JS 函数误报为缺失数据源的问题，同时兼容原生内嵌 API 数据源。保持本体插件与原生能力松耦合：原生资源沿用原生合法性规则，本体插件负责新增契约，发布层负责整合依赖、快照和诊断。

## 根因与证据

- 截图中五个 Action 经只读核对均属于 `JS Functions / js-plugin`，其 datasource 只有插件标识，没有独立数据源 ID。
- `ReleaseDatasourcePinExtractor.extractPins` 在识别资源类型之前统一要求 `datasource.id` 非空，因而产生阻塞诊断。
- `NewActionServiceCEImpl` 原生校验区分 JS 与其他 Action，并支持没有独立 ID 的内嵌 datasource；不能把缺少独立 ID 一律解释成配置损坏。
- `ApplicationReleaseSnapshotBuilder` 已将候选 actions 纳入快照。无需为了记录 JS 或内嵌 API 而创建虚构数据源、修改持久化模型或丢弃 Action。
- `ReleaseDiagnostic.message` 包含完整资源路径，发布面板又显示 `path`，形成重复且难以阅读的长行。

以上根因来自代码追踪和只读数据检查。修复后已完成定向自动化回归；现有浏览器会话重定向登录，未完成真实发布验收。本轮没有重新部署或重启业务服务，运行服务的确切提交版本未核实，不能将本地测试通过表述为部署成功。

## 已选方案与边界

不采用仅跳过 JS 的临时补丁，也不采用所有空数据源 ID 一律放行。按原生类型和引用语义分类，避免在本体扩展中复制另一套原生校验规则。

| 资源类型 | 发布扩展职责 | 保留的原生职责 |
| --- | --- | --- |
| JS 函数 | 不要求独立数据源 ID，不生成独立 datasource Pin；保留 Action 和快照内容 | JS 配置、语法及原生发布处理 |
| 合法内嵌 API | 不要求独立数据源 ID，不生成虚构 Pin；内嵌配置随 Action 进入快照 | 内嵌配置合法性及原生执行规则 |
| 已保存原生数据源 | 保留真实引用及现有 NATIVE Pin，不新增本体专属字段要求 | 原生数据源配置、权限及执行规则 |
| 本体插件数据源 | 严格检查引用、项目版本、元数据快照、摘要和相关契约 | 继续使用原生 datasource/query/action 管线 |

“不生成独立 Pin”不等于跳过所有检查或不发布该 Action。JS 调用的其他查询仍按对应查询资源检查依赖，不新增 JS 源码解析器。

类型识别使用现有 Action 插件类型和插件身份，不根据函数名、显示名称或单纯 ID 是否为空判断。只对已确认的合法原生结构放弃不适用的独立 ID 检查；未知类型、结构矛盾和真实引用缺失不能借此无条件放行。本体识别失败也不能降级为普通原生资源以绕过校验。

实施时追踪并复用现有原生校验入口。若某类原生错误只在既有保存或正式发布阶段检查，不把新增预检包装成覆盖所有原生错误的完整验证器，更不引入可能写库的重复校验路径。

## 数据流与兼容

1. 沿用现有候选应用、Action 和数据源加载流程。
2. 提取器先识别资源语义，再提取真正独立的数据源引用；本体引用进入严格契约检查。
3. 依赖扫描保留 Action 依赖；只有真实数据源引用才产生独立数据源依赖。
4. 快照保留全部候选 Action 及其合法内嵌配置，继续执行既有敏感信息脱敏和摘要计算。
5. 预检结果、创建发布版本和正式发布保持同一职责边界，沿用原生发布协调流程。

保持 `ReleaseDatasourcePin` 的非空 ID 契约，不给 JS/内嵌资源伪造 ID，不新增 Pin 类型或数据库迁移。不改写已有发布快照，不自动发布用户应用，不清理业务 Action。若实测发现既有脱敏不能覆盖内嵌配置，必须修复并验证后才能将该路径标记为通过。

## 诊断显示

- 保持现有 `severity`、`code`、`path`、`message`、`details` 结构。
- 新诊断的 message 只表达原因，path 单独表达位置；使用结构化字段定位，不通过裁剪异常字符串猜测字段路径。
- 适用时在 details 中提供 `actionId` 和 `actionName`，用于辅助显示；名称不替代 ID 或完整路径，不包含执行体、连接串或凭据。
- 前端分开呈现摘要、资源名称和技术路径，长路径及消息允许换行，不撑宽发布弹窗。
- 缺少名称的历史诊断仍可正常展示。英文为新增文案源语言，通过现有 i18n 提供中文，不进行发布面板全面重构或中文化。

## 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 合法 JS Action 无独立数据源 ID | 不再出现数据源 ID 缺失误报，Action 留在快照中 |
| 合法内嵌 API 无独立数据源 ID | 不误报；配置保留且敏感信息仍被脱敏 |
| 已保存普通数据源 | 正常保留真实依赖和现有 Pin；不要求本体字段 |
| 本体配置缺少 ID、版本、快照或摘要 | 继续产生明确阻塞诊断，不降级绕过 |
| 真正缺失或矛盾的资源引用 | 按所属校验职责报错，不能因空 ID 放行 |
| JS、内嵌 API、普通查询和本体查询混合 | 分类一致，依赖和发布内容不丢失 |
| 长路径及缺少 Action 名称的诊断 | 原因与路径不重复，弹窗不横向溢出，回退展示正常 |
| 创建版本及正式发布 | 维持原生发布链，合法应用不再被该误报阻塞 |

先用回归测试复现 JS 误报，再验证上述边界；补充提取器、依赖/快照及发布面板的定向测试。集成或浏览器验收使用授权的测试环境，不以单元测试替代真实发布结果，不在诊断阶段修改或发布用户业务应用。

## 不在本轮范围

- T9、正式本体契约重新设计或 Action Server 协议调整。
- 原生插件通用校验框架、全插件能力注册系统及第二套执行链。
- 页面 URL、地图、图表或其他编辑器模块改造。
- 绕过发布预检、权限、功能开关或将阻塞问题一律降为警告。
